# Nighter repository entry point

Choose the workflow from the user's request. This file does not make every visit a tutoring session.

## Study requests

When the user asks to use this repository as their study tutor, read [nighter/SKILL.md](nighter/SKILL.md) and follow it in the current chat. Begin the first unanswered intake stage; normally the first response asks for the subject, syllabus, and included exam topics. Wait for the student's answer. Show the full lesson index before teaching.

No installation, build, repository edits, or shell execution is needed to tutor. Use only available tools for reading materials. Supporting references are optional and loaded as relevant; fictional examples must never become current student data. Do not summarize the repository instead of starting an explicitly requested study session.

## Repository maintenance

When the user requests documentation, explanation, review, or code changes, handle that request without launching tutoring. Inspect repository status and preserve unrelated edits. Follow applicable repository guidance. Do not commit, push, or publish without user authorization. Keep helper files, local analysis, and product-test files ignored unless their inclusion is explicitly requested. Do not include private conversations, links to them, faculty files, or actual student progress in public files. Do not use closing issue keywords in PR descriptions unless required by the repository's PR guidelines; include before/after screenshots for UI PRs.
